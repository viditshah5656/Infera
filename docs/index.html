02 / how it works

Follow one request.

The site explains the request path at the same level a developer thinks about it: client → gateway → router → adapter → model.

Request lifecycle

A normal completion call enters Infera locally and is routed without your application needing to know the backend implementation.

1. ClientSDK, curl, browser, IDE
2. Gateway127.0.0.1:8081
3. Routerchooses adapter
4. Adapterspeaks backend-specific protocol
5. Runtimegenerates the response

Example request

Designed around familiar OpenAI-compatible semantics.

POST http://127.0.0.1:8081/v1/chat/completions

{
  "model": "qwen-local",
  "messages": [
    {"role":"user","content":"Hello Infera"}
  ],
  "stream": true
}

04 / trust

Trust should be designed in.

Infera is open source and local-first, but the website is careful about what it can and cannot promise.

◎

Open source

Inspect the repository, architecture documentation, attribution, license and installer scripts before running anything.

github
⌂

Local by default

The gateway is designed around localhost. GitHub Pages hosts the interface; it does not execute your local runtime.

127.0.0.1
✓

Honest installation

First-time browser installs still require a user action. A future signed native installer is the right path for stronger OS-level trust.

transparent

Where the project came from

Infera includes substantial original work around the local gateway, routing, compatibility layers, workspace UI and documentation. The repository also gives explicit credit to the original upstream project by Sophomoresty.
